# Environment Configuration Setup

## Quick Start

1. **Copy the example file:**
   ```bash
   cp .env.example .env
   ```

2. **Update `.env` with your values:**
   ```bash
   # Edit .env and set your Snowflake account, warehouse, API key, etc.
   nano .env
   ```

## Configuration Variables

### Snowflake Configuration
- `SNOWFLAKE_ACCOUNT` - Your Snowflake account identifier (e.g., tqmttqp-hw26207)
- `SNOWFLAKE_HOST` - Snowflake host (e.g., tqmttqp-hw26207.snowflakecomputing.com)
- `SNOWFLAKE_WAREHOUSE` - Default warehouse (e.g., COMPUTE_WH)
- `SNOWFLAKE_DATABASE` - Default database (e.g., AMUSEMENT_PARK_DB)
- `SNOWFLAKE_SCHEMA` - Default schema (e.g., ANALYTICS)

### MCP Server Configuration
- `SERVER_PORT` - HTTP port for MCP server (default: 8080)
- `MCP_API_KEY` - API key for authenticating tool invocations (required for security)

### Identity & Entra ID Configuration
- `ENTRA_MAP_TABLE` - Snowflake table for Entra ID → Snowflake user mapping
- `CACHE_TTL_SECONDS` - How long to cache identity mappings (default: 300 seconds)
- `DEFAULT_ENTRA_USER` - Fallback user if mapping not found (default: analyst@amusementpark.com)

### Cortex Agent Configuration
- `AGENT_FQN` - Fully qualified name of Cortex Data Agent (e.g., AMUSEMENT_PARK_DB.ANALYTICS.AMUSEMENT_PARK_INSIGHTS_AGENT)

### Logging
- `LOG_LEVEL` - Logging level (INFO, DEBUG, WARNING, ERROR)

## Security Notes

⚠️ **IMPORTANT:**
- `.env` file is ignored by git and should NEVER be committed
- Never share `.env` file with sensitive values
- Use `.env.example` as a template for documentation
- Rotate `MCP_API_KEY` regularly in production
- In SPCS, sensitive values are passed via Snowflake Secrets, not .env

## Local Development

For local testing with `make local`:
```bash
# Load env vars from .env
make setup
make local
```

## SPCS Deployment

For production deployment to Snowflake SPCS:
1. Non-sensitive config (SNOWFLAKE_* variables) can be in the service spec
2. Sensitive values (MCP_API_KEY) must be in Snowflake Secrets and injected at runtime
3. The SPCS service spec has a `secrets:` section that maps Snowflake Secrets to env vars

See [README.md](README.md#deployment) for SPCS deployment details.
